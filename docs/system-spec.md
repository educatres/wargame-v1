# 系統規格書

## 1. 系統定位

本系統是「戰場情境想定生成、課堂回合推演、決策歷程分析與課後檢討平台」，不是即時作戰決策系統。

第一版的設計原則：

1. 純前端、無後端；離線規則生成可獨立使用，外部 AI 為使用者自行啟用的選項。
2. 所有兵力與效能均採合成抽象指數。
3. 教師保有最終裁決權。
4. 評量決策過程，不只評量結果。
5. 公開來源、合成資料與學生輸入分層管理。

## 2. 使用者角色

### 教師／白方
- 設定學習目標及難度。
- 生成、修改與發布想定。
- 控制事件、情報揭露及回合結算。
- 檢視決策時間線與課後檢討。

### 藍方學生
- 分析任務、情報與限制。
- 提出行動方案及資源配置。
- 說明決策理由與風險。

### 紅方學生
- 從對手角度提出施壓、反制與欺敵行動。
- 檢驗藍方方案的脆弱假設。

### 琥珀方學生
- 規劃美軍ISR、後勤、網路、外交與有限存在支援。
- 處理政治約束及升級風險。

## 3. 功能模組

### 3.1 想定生成
輸入：
- 教學重點
- 難度
- 回合與時間尺度
- 情報不確定度
- 民事壓力
- 美軍支援程度
- 天候
- 教師限制

輸出：
- 情境背景
- 學習目標
- 成功條件
- 限制
- 事件排程
- 情報排程
- 初始角色狀態

### 3.2 回合推演
每方每回合提交：
- 行動
- 區域
- 資源投入
- 決策理由

結算考量：
- 準備指數
- 持續性
- 指揮品質
- 情報品質
- 資源投入
- 天候
- 事件
- 美軍支援
- 隨機不確定性

### 3.3 情勢視覺化
- 抽象區域格網
- 各方行動標記
- 事件及天候提示
- 狀態指標

### 3.4 教學實驗
攔截資源配置採合成公式：

```text
adjusted_p =
  base_p
  × (0.6 + 0.4 × detection)
  × (0.75 + 0.25 × readiness)
  × (1 - 0.08 × (sea_state - 1))
  × (1 - 0.12 × jamming)

P(at least one success) = 1 - (1 - adjusted_p)^shots
```

限制：
- 僅供比較同一組合成假設下的資源配置。
- 不代表任何真實武器。
- 未建模共同失敗、射擊窗口、同時多目標與指管延遲。

### 3.5 課後檢討
- 回合時間線
- 決策與理由
- 事件及結果
- 最終狀態
- 資源消耗
- 民事風險
- 主要風險提示
- JSON／CSV匯出

## 4. 前端架構

```text

  ├─ 想定生成
  ├─ 回合推演
  ├─ 課後檢討
  ├─ 資料庫

  ├─ TurnResolver
  ├─ StateStore
  ├─ AARRenderer

```

## 5. 資料儲存

第一版：
- 內建資料：JavaScript物件。
- 使用者進度：localStorage。
- 可攜式檔案：JSON。
- 分析資料：CSV。

未來版：
- IndexedDB。
- Firebase／Supabase／校內API。
- 多使用者房間與角色權限。

## 6. LLM 介接

目前提供統一的瀏覽器端介面，支援長庚 CGU LLM API、OpenAI Responses API、Google Gemini API 與 Anthropic Claude Messages API。使用者可修改模型名稱及 endpoint；API Key 僅存在輸入欄位，不寫入本機進度或匯出檔。

介接概念：

```javascript
async function generateScenarioText(context) {
  // offline rules provider
  // CGU / OpenAI / Gemini / Claude provider
}
```

必要安全措施：
- 預設僅使用合成資料。
- 不將受限資料傳送至外部模型。
- 教師核准後才能發布。
- 保留Prompt、模型版本及修改紀錄。
- LLM只產生敘事與教學問題，不直接決定真實武器效能。
